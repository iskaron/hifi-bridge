# Card layout from measured builds

Generated by `os/tools/size_plan.py` from the image checks of real builds (**BUILD**: built and taken apart in Docker, nothing booted). MiB = 2^20 bytes, GB = 10^9 bytes. Layout: DECISIONS #120, numbers: `os/storage.json`, reasoning: docs/PERSISTENCE.md.

Builds: rpi3_64 only, rebuilt incrementally on 2026-11-20 from commit 85b25d3 (final polish P1, layout of DECISIONS #120). rpizero2w_64 and rpi4_64 still have the package-6 layout until their rebuild (P2).

## Arithmetic

* **Slot** 384 MiB: largest rootfs in use 193.3 MiB = 50 % (limit 80 %) -> **ok**; 191 MiB left for later releases.
* **Largest bundle**: measured compression bundle / rootfs used = 0.381; a completely full slot -> 384 x 0.381 = 146 MiB <= budget 192 MiB (slot / 2) -> **ok**.
* **Data before growth** 256 MiB (`mke2fs -b 4096 -i 65536`): need = bundle 192 + free-space margin 16 + state 8 = 216 MiB available to the bridge; measured 225.8 MiB -> **ok**.
* **Card** = 4 + 64 + 2 x 384 + 256 = 1092 MiB = 1.145 GB <= usable 2 GB card 1.80 GB (1717 MiB) -> **ok**. After the first-boot growth the data partition has ~881 MiB on such a card (~14.1 GiB on a nominal 16 GB card, the recommendation).
* Built images use this layout: **ok**.
