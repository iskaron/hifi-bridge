## HIGH
H1 WebUI memory exhaustion without login: webui/server.py:65-68 read_form: Content-Length -1 passes `n > MAX_BODY`, rfile.read(-1) reads to EOF, before session/CSRF; POST /login without Origin passes same_origin. 150 MiB -> RSS 28->180 MiB; OOM kill at MemoryMax=256M. Fix: reject negative/non-numeric/too large with 400/413, capped read + socket timeout, handle Transfer-Encoding explicitly (refuse chunked). Test: raw socket POST /login Content-Length -1 + 1 MiB body -> 400, RSS growth < ~1 MiB. (repro_webui.py a)

H2 Slow/dead LMS -> systemd watchdog restart loop: core/controller.py:318-336 tick() holds controller lock across every LMS JSON-RPC; app.py:140-148 heartbeat only at top of control loop; service.py:341-358 health()->status()->controller.status() waits for same lock; service.py:311-336 watch loop calls status(); HEARTBEAT_STALE_S=5. LMS down while phone plays: two observe calls per tick, 3 s timeout per attempt/address, getaddrinfo without timeout (~10 s per nameserver), A+AAAA doubles. repro_watchdog.py: 10 s per call -> 0 pings in 150 s, systemd kills every ~30 s for whole outage; WebUI and /healthz block. Contradicts SERVICE_SUPERVISION.md ("degraded never restarts") and PRODUCT_SPEC (BT stays connected through LMS outages). Fix: LMS I/O outside the lock (snapshot under lock, I/O, re-check session id/generation under lock), lock-free status snapshot, tick time budget, resolve LMS name in a worker with timeout + cache, heartbeat semantics independent of I/O duration. Test: fake LMS sleeping 10 s per call, phone playing, Watchdog with fake notifier, 60 s: no withheld pings, health() < 0.5 s. Ownership rules must stay intact (revalidation, session identity).
